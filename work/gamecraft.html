Cloud Systems · 2023

A community platform for unfinished game ideas.

A cloud-based platform where developers submit game concepts, the community reviews them, and the best ideas rise through voting.

Year
2023
Context
Cloud Application Development
Role
Team project
Stack
React · Node.js · cloud
01 / Overview 02 / Approach 03 / What I built 04 / Outcome

Overview

Game ideas usually die in private notes. GameCraft was built as a shared surface: register, submit a concept, browse what others are building, and vote on what should move forward.

The project was a full-stack cloud application, split into a frontend and backend with a clear API between them. The aim was not to build every feature imaginable, but to make the core loop work end to end.

Approach

01 / Start with the loop

Submit → browse → review → vote. Every technical decision was judged against whether it made that loop clearer or faster. Features that did not serve it were left out.

02 / Split the system deliberately

The frontend and backend were separate applications with a defined API. That forced us to be explicit about data models, authentication, and what each side was responsible for.

03 / Design for the community

The platform is only useful if people can see other ideas and react to them. The interface prioritises browsing and voting over heavy configuration.

What I built

  • A React frontend for browsing, submitting, and reviewing game ideas.
  • A Node.js backend with API routes for users, ideas, and votes.
  • Registration and authentication flows.
  • Cloud deployment with separate frontend and backend repositories.

Outcome

The project made one thing clear: most of cloud development is contract and state management, not infrastructure. Ambiguity in a data model becomes a bug in two places at once.

Working across frontend and backend also changed how I review systems. I now look for the shape of the data before the shape of the interface.
