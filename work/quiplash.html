Real-Time Product · 2023

Rebuilding a party game as a real-time system.

A full-stack recreation of Quiplash, prompts, answers, voting, scoring, and a server that keeps every player in sync.

Year
2023
Context
Cloud Application Development
Role
Team project
Stack
Node.js · Express · Azure Functions · Cosmos DB
01 / Overview 02 / Approach 03 / What I built 04 / Outcome

Overview

Quiplash is simple to explain and surprisingly demanding to build. Every round depends on shared state: who has answered, who has voted, what the score is, and what happens when someone disconnects.

The project recreated the game across a web client, a Node.js server, and a set of Azure services. It was an exercise in making a real-time experience feel simple while the system underneath stays coordinated.

Approach

01 / Model the game loop

The core is a state machine: collect answers, present them, collect votes, score the round, move on. Getting that sequence explicit made the UI and the server easier to reason about.

02 / Keep players in sync

Every player needs the same view of the round. The server owns the state, and the client renders what it receives, rather than trying to reconstruct the game locally.

03 / Use managed services where they fit

Azure Functions handled event-driven pieces, Cosmos DB stored game data, and we experimented with Cognitive Services for content handling. The goal was to understand the trade-offs, not to use every service available.

What I built

  • A Node.js and Express server for the game loop and shared state.
  • A responsive client for prompts, answers, voting, and scores.
  • Azure Functions and Cosmos DB integration for cloud-side logic and persistence.
  • Exploration of Azure Cognitive Services for content handling.

Outcome

Real-time features expose every weak assumption about state. The project made cloud services feel like design decisions rather than checkboxes: each one changed what the system could do and what it cost to operate.
