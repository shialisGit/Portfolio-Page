Model Testing · 2024

A workbench for inspecting model behaviour.

An interactive Streamlit application for running YOLOv8 detection and segmentation on images and video, built to make model failures visible.

Year
2024
Context
Dissertation tooling
Role
Individual

01 / Overview 02 / Approach 03 / What I built 04 / Outcome

Overview

A score tells you a model passed a test. It doesn't tell you why it missed the object that mattered. I wanted a fast way to move from a model checkpoint to a visual answer.

The app was built as part of my dissertation work on occlusion, but it is useful for any YOLOv8 model: upload an image or video, run detection or segmentation, and inspect the result directly.

Approach

01 / Keep the loop short

The interface is deliberately plain. The goal was not to build a product; it was to remove every step between a question about the model and visual evidence about the model.

02 / Support the two tasks that matter

Detection answers “where is it?” Segmentation answers “which pixels belong to it?” The app supports both, so the same input can be inspected at two levels of detail.

03 / Test on real inputs

Images and video both matter. A model that performs well on a still frame can behave very differently when objects move, blur, and overlap over time.

What I built

  • A Streamlit interface for image and video input.
  • YOLOv8 detection with bounding boxes and segmentation with masks.
  • Controls for running inference and inspecting the output visually.
  • A testing workflow for comparing accuracy and speed across inputs.
View on GitHub ↗

Outcome

The app shortened the loop between hypothesis and visual evidence. It made the limits of the detector obvious: small, overlapping, and partially hidden objects were consistently harder, and a good aggregate score could hide a lot of ugly individual cases.

That is the value of a testing tool. It turns “the model seems fine” into a concrete observation about when it is not.
